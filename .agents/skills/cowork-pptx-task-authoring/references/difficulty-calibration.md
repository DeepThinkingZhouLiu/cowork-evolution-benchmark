# PPTX 难度设计与实测校准

## 两层标签

- `design_target`：制题阶段的候选层级，只用于控制题池结构，写入适配记录和建设台账。
- `difficulty_level` / `difficulty_tier`：冻结协议下的实测层级。真实回放前必须同时为 `unassigned`。

Rubric/Judge 只判断答案质量。难度来自同一 Agent、工具、时间和资源预算下的实际成功率、得分与执行负担。

## PPT 域内设计目标

| 目标 | 典型结构                                                                 |
|------|--------------------------------------------------------------------------|
| L1   | 单一明确输入；局部创建或编辑；事实直接给出；约束少且无冲突；短路径可完成。 |
| L2   | 多页或多素材；需要保持未修改内容、模板或叙事一致；有一次数据转换或审计。   |
| L3   | 跨应用取证、跨文件整合、受众改写或数据分析与可视化耦合；约束相互依赖。     |
| L4   | 长时程、多阶段、动态更新、冲突来源、隐藏状态或失败恢复；强 Agent 仍易漏检。 |

页数、文件数、图片数和人工耗时只能作为描述特征，不能单独决定难度。L4 也不能靠模糊审美、故意缺文件或不合理超时制造。

## 建设配比

PPT 模块最终保留 60 题，目标为：L1 12、L2 18、L3 18、L4 12。现有题和新增题先标 `design_target`，全部通过 Harbor 与 Judge 门槛后再统一回放。

## 冻结回放协议

1. 固定三个强 Agent Harness 配置、模型版本、工具权限、上下文策略、单题 30 分钟、2 CPU、4 GiB 内存、12 GiB 存储和默认无公网。
2. 每个 Agent Harness 对每题独立运行 3 次，共 9 次；基础镜像、任务 commit 和随机种子写入清单。
3. 记录 normalized reward、严格通过、运行时间、Agent 步数、工具错误、超时和基础设施失败。基础设施失败重跑且不计入难度。
4. 用 9 次运行的平均 reward 与严格通过率为主要依据；耗时、步骤和恢复行为只用于同档排序及诊断。
5. 难度筛选所用轨迹不得再进入论文正式评测结果；final 集不得用于 Harness 进化或 Epoch 选择。

## 晋升规则

- L1 / Easy：严格通过率至少 0.78，且平均 reward 至少 0.80。
- L2 / Medium：严格通过率在 0.44–0.77，或平均 reward 在 0.55–0.79。
- L3 / Hard：严格通过率在 0.11–0.43，或平均 reward 在 0.25–0.54。
- L4 / Expert：严格通过率至多 0.10，且平均 reward 低于 0.25。

边界冲突时以平均 reward 所在档为主，并查看错误是否来自任务能力而非 Judge、依赖或环境。若某题所有 Agent 都为 0，必须先证明 Oracle、人类复核和环境稳定；不可解或主要靠猜审美的题直接淘汰，不得作为 Expert。

若实测数量不满足 12/18/18/12，从已审计但未晋升的 Seed 中替换，不通过修改阈值或篡改 Judge 强行凑档。
