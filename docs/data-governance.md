# 数据治理规范

## 数据分层

- 原始层：未经筛选的真实请求、输入、轨迹和产物，只能在受控存储中访问。
- 候选层：完成文件恢复、基础脱敏和可用性筛选，但尚未具备完整 Judge。
- 制题层：正在补充 Golden、Rubric、环境和校准样本的任务。
- 发布层：通过质量门槛并进入某个不可变 Benchmark Release 的任务。

原始层和候选层不能因为目录结构类似 Harbor 就被直接称为正式 Benchmark。

## 必需记录

每条任务必须记录：

- 原始来源与获取时间。
- 源文件和转换后文件的 SHA256。
- 许可、保密和再发布条件。
- 是否真实用户请求、是否人工改写、是否包含合成内容。
- 隐私审查状态和审查人。
- 转换脚本版本和任务版本。
- 泄漏组编号及其计算依据。
- 允许用于反馈、选择、最终评测或仅内部分析的范围。

## 防泄漏

泄漏检查至少覆盖：

- 文件字节哈希和规范化文档哈希。
- 图片感知哈希和页面渲染相似度。
- 指令文本近重复和模板骨架。
- 同一客户、项目、报告、论文或数据源。
- 相同 Golden 模板、母版或工作簿结构。
- 同一任务家族的参数替换变体。

任何一项高度相似的任务应进入同一泄漏组。数据划分以泄漏组为单位完成，而不是逐条随机抽样。

## 发布策略

对于无法公开的真实企业任务，推荐发布协议、Schema、脱敏开发集和任务统计，同时把密封测试集放在托管评测服务中。评测服务只返回必要结果，不返回原始文件、Golden、完整 Rubric 或 Judge 提示词。
