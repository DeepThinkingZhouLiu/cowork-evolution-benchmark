| Harness              | 升级题新作答 | 旧证据缺失补跑 | 复用旧结果 | 最终总数 |

- 原配置：zcloud Provider、Sonnet 5、原冻结 CLI/SDK 版本与预算；每题独立 Harbor 容器、独立输入/输出和会话，Agent 看不到 Golden/Judge。
- Word 沿用确定性代码 Judge，不加入 VLM。
- 只有完整题包哈希等于 v0.2 且旧试验与重评分文件均存在的结果可复用。11 份旧汇总虽然没有记录原试验路径，但已在原始任务目录唯一找回对应的完成记录，现恢复证据引用。
- 用户确认仅重测升级题后，共计划 51 次有效新作答、129 份旧结果复用；初始 62 次计划另行归档。调整前已启动的额外旧题保留运行证据，不纳入新版主结果，未开始的额外任务不再发起。
- 新旧结果逐条记录来源，不能把汇总称为全量重新运行。
- 每 Harness 内串行，三条流水线并行；每题一次有效能力试验，只对基础设施失败有限重试，失败不记为 0 分。
- 运行中缺失项保持未完成，只有 60/60 时才填该 Harness 的整体均分。每题 Panel 分数为三个 Judge 得分均值，经验难度为 `1 - Panel`；按 Panel 降序依此前配比划为 Easy 12、Medium 18、Hard 18、Expert 12。
- 边界同分时按原预计工作量、任务编号稳定排序，并明确报告同分跨档，不能据此声称同分题具有实测难度差异。本轮是分数分位试校准，不改 `task.toml` 的正式难度标签。
- OpenHands 因预算耗尽可能未落盘 usage；只有日志存在真实 Agent Action 和实际 token 用量时，才把该预算超时视为能力试验并按 Judge 计分。取首次有效试验，不取重试最高分；额外重试证据保留。
- 实验产物位于同级 `agent-harnesses/runs/docx-v0.3-hardened-panel-20260908/`；`evaluation-plan.json` 为计划，`panel-summary.json` 为进度/汇总，各 Harness 的 `results.json` 保存逐题分数和来源。

入口为 `tools/run_docx_hardening_panel.py --only-upgraded`，先额外加 `--prepare-only` 核验，再用同一参数运行；执行期间任务树若变化，Runner 会停止，以免混合快照。调度器重启先等待当前 Harness 已有单题结束，避免重复作答。凭据只在运行时读取本机配置，不写入仓库或实验清单。

180 份结果齐全后，自动生成 `difficulty.md`（四档汇总表）、`difficulty.csv`（60 道题逐题分数与分档）和 `difficulty.json`（公式、同分边界及完整结果）。没有跑完时不生成假完整难度表。
