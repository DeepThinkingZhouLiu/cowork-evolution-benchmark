# 评测规范

## 两层评测

单题 Judge 与 Benchmark 汇总必须解耦：

- Task Judge 打开一个任务的候选办公产物，输出逐条 Rubric 结果和证据。
- Benchmark Evaluator 汇总标准单题结果，比较不同模型或 Harness，并生成统计报告。

Evaluator 不关心任务是 PPTX、DOCX 还是 XLSX；文件类型差异由任务自己的 Judge 消化。

## Judge 顺序

```text
文件门槛
→ Office 结构与数值确定性检查
→ 内容、引用与跨文件一致性
→ 页面渲染和视觉检查
→ 语义或专业质量检查
→ 独立聚合分数
```

- 文件门槛检查存在性、格式、可打开性、路径和损坏关系。
- 确定性检查文本、公式、数据、页数、元素、样式、未修改区域和引用来源。
- 视觉检查溢出、遮挡、对齐、配色、可读性和页面一致性。
- 需要主观视觉判断的 PPTX/PDF 任务可以调用固定 Codex CLI 和受控 VLM Provider；每题必须有自己的视觉 Rubric。确定性分和视觉分分别保存，并按任务声明的 `0.7 / 0.3` 聚合。
- Renderer、Codex、VLM 或 Provider 失败属于评测基础设施失败，必须使本次评分无效并重跑，不能静默记为 Agent 零分。

## 分数定义

对正向判据，`s_i` 表示满足程度；对惩罚判据，`s_i` 表示违规严重程度，二者都在 `[0, 1]`。

```text
正向得分 = Σ(正向权重 × 满足程度)
惩罚得分 = Σ(|惩罚权重| × 违规严重程度)
归一化分数 = 截断((正向得分 - 惩罚得分) / 正向权重总和, 0, 1)
```

门槛项失败时可以封顶或直接判失败，但门槛逻辑必须写入 Rubric 和 Judge 结果。

## 结果汇总

每个模型或 Harness 的报告至少包含：

- 任务覆盖数、平均 Reward、严格通过率和非零题数；
- 按模块、任务家族、结构难度和评测 split 的分数；
- 超时、错误、无产物、策略违规和评测基础设施失败；
- Token、延迟、成本和重复运行稳定性（若 Runner 提供这些字段）。

不同模型或 Harness 的比较必须使用相同任务、版本、预算、工具权限、随机种子和重复协议。缺失结果不能从分母中静默删除；基础设施失败单独记录并重跑。

## Judge 校准

每个任务至少准备：Golden 高质量正样本、存在局部问题的中等样本、缺少关键要求的负样本，以及文件损坏或无交付物的门槛失败样本。校准报告记录逐条 Rubric 分布、重复评分稳定性、人工排序与 Judge 排序的一致性，以及容易被投机利用的案例。
