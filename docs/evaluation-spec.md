# 评测规范

## 两层评测

单题评测与 Benchmark 汇总必须解耦：

- Task Judge 解析一个任务的真实办公产物，输出逐条 Rubric 结果。
- Benchmark Evaluator 汇总标准单题结果，比较 H0 与 Candidate，计算统计指标和论文报告。

Benchmark Evaluator 不关心任务是 PPTX、DOCX 还是 XLSX，也不直接调用视觉模型。文件类型差异由 Task Judge 负责消化。

## Judge 分层

推荐按以下顺序判分：

```text
文件门槛检查
-> Office 结构与数值确定性检查
-> 内容与引用检查
-> 页面渲染和视觉检查
-> 语义或专业质量 Judge
-> 独立聚合分数
```

- 文件门槛：文件存在、格式正确、能打开、路径正确、无损坏。
- 确定性检查：文本、公式、数据、页数、元素、样式、未修改区域和引用来源。
- 视觉检查：溢出、遮挡、对齐、配色、可读性和页面一致性。
- 语义检查：信息覆盖、专业判断、逻辑结构和事实性。

能够用程序准确判断的内容不得退化成 LLM 主观评分。

对于需要主观视觉判断的 PPTX/PDF 产物，第一版使用固定 Codex CLI 作为评分
Harness，通过受控 Provider 调用 VLM。每题必须另有任务特定视觉 Rubric；确定性
分和视觉分分别保存，按 `0.7 / 0.3` 聚合。完整协议见
[`codex-vlm-judging.md`](codex-vlm-judging.md)。

## 分数定义

对正向判据，`s_i` 表示满足程度；对惩罚判据，`s_i` 表示违规严重程度。二者都位于 `[0, 1]`。

```text
正向得分 = Σ(正向权重 × 满足程度)
惩罚得分 = Σ(|惩罚权重| × 违规严重程度)
归一化分数 = 截断((正向得分 - 惩罚得分) / 正向权重总和, 0, 1)
```

门槛项失败时可以把最终分数封顶为指定上限，或直接判为失败。门槛逻辑必须写入 Rubric 和 Judge 结果，不能隐藏在临时代码分支里。

第一版统一使用 `0.7` 作为成功阈值。任务可以记录建议阈值，但正式 Release 中不得逐题任意调阈值以迎合已有模型结果。

## 配对比较

H0 与 Candidate 必须在相同任务、模型、预算、工具版本和随机种子下运行。比较至少输出：

- H0 与 Candidate 的平均分和成功率。
- Candidate 新解决、仍然解决、退化和仍未解决的题目数量。
- 平均分变化和成功率变化。
- 配对 Bootstrap 置信区间。
- Token、延迟和成本变化。
- 超时、错误、无产物和策略违规数量。

缺失结果、超时和运行错误不能从分母中静默删除，应按评测 Policy 记为零分或使运行无效。

受测 Agent 没有交付核心文件或交付损坏文件属于任务失败，可以记零分。渲染器、
Codex、VLM 或 Provider 失败属于评测基础设施失败，必须使该题本次评分无效；不得
记成 Agent 的零分，也不得静默回退成纯确定性分。

## Judge 校准

每个任务至少准备以下校准样本：

- Golden 或人工确认的高质量正样本。
- 保留主要内容但存在局部问题的中等样本。
- 缺少关键要求或包含明显错误的负样本。
- 文件损坏、格式错误或没有交付物的门槛失败样本。

校准报告需要记录逐条 Rubric 分布、多次评分标准差、人工排序与 Judge 排序的一致性，以及容易被 Reward Hacking 利用的案例。
