# 甲方 Office 数据需求到 Benchmark 的改造说明

## 参考文件

参考文件为 2026-08-12 生成的《【外发】Cowork RL Office 数据需求说明》，共 10 页。该文件适合作为单题交付合同和质量验收清单，但它本质上是甲方采购验收规格，不等同于可发表 Benchmark 的研究协议。

## 可以直接沿用的部分

- 单题采用 Harbor 目录：`instruction.md + task.toml + rubric.json + environment/ + data/input_files/ + solution/ + tests/`。
- 输入文件必须随包交付，不能依赖临时外链。
- 每题至少 6 条原子 Rubric，包含权重、类型、维度和判分方法。
- Judge 要一键运行，并区分确定性、视觉和语义判据。
- 同一输出重复评分至少 5 次，随机 Judge 的单条标准差小于 `0.05`。
- 必须提供正例、中等例、负例和门槛失败例，证明 Judge 有正确偏序。
- 难度要靠多模型、多次 Rollout 证明，不能由制题者主观声明。

## 不能直接照搬的部分

甲方文档按 PPT、Excel、All 和少量任务类型组织，适合验收批量数据，却不足以分析 Harness 为什么进化。Benchmark 需要额外增加任务家族、通用能力、输入模态、依赖范围、约束画像、泄漏组和数据分区。

甲方文档中的数量也存在需要澄清的地方：表格各行预期数相加与后文“第一批次总数据量 330 条”不一致。Benchmark 不继承这些采购数量，而是根据研究功效、制题成本、领域覆盖和最终密封评测预算单独确定样本量。

甲方文档允许联网任务和素材检索，但公开 Benchmark 必须先解决来源许可、网页快照、时间冻结和可复现性。第一批公开端到端样例默认离线；需要联网的题单独进入可冻结的 Web Track。

## 两套能力编号

甲方已经定义 `C1-C13`，本项目在 `supplier_capability_ids` 中保留原含义：

| 编号  | 甲方原定义                         |
|-------|------------------------------------|
| `C1`  | 素材搜集与检索                     |
| `C2`  | 内容结构化与大纲生成               |
| `C3`  | PPT 指令执行                       |
| `C4`  | 版式、主题与配色设计               |
| `C5`  | 图表与数据可视化                   |
| `C6`  | 讲稿与演讲备注生成                 |
| `C7`  | 文档到结构化数据抽取               |
| `C8`  | 公式与领域计算建模                 |
| `C9`  | 格式转换                           |
| `C10` | 交付物落地与自检                   |
| `C11` | 多模态输入理解                     |
| `C12` | 跨格式多交付物                     |
| `C13` | 交互 HTML 报告或 Deck              |

这些编号偏向工具和交付形式。论文需要跨 Word、Excel、PPT 比较通用能力，因此另设 `K1-K13`，描述内容抽取、证据落地、数据转换、计算、分析、写作、编辑保持、视觉表达、模板遵循、跨文件整合、一致性传播、审计质检和工作区编排。两套编号不能混用。

## 当前 42 个公开任务的定位

当前仓库为 42 个任务家族各提供 1 个端到端公开样例。它们有真实可打开的输入和 Golden、可执行参考解法、至少 6 条 Rubric、确定性 Judge 与来源哈希，用于验证：

- 分类是否覆盖主要 Office 工作流。
- Harbor 合同是否足以表达不同交付物。
- Judge 接口、隐藏侧隔离和跨文件一致性是否可实现。
- 后续从 273 条真实轨迹或开源 Seed 转题时有没有稳定模板。

这些样例使用无隐私合成业务事实并明确标记 `synthetic = true`。它们是开发集和 Judge 回归夹具，不能因为端到端可运行就直接冒充“真实用户 Benchmark 数据”。进入论文正式 Release 前，仍需替换或补充真实来源、人工 Golden 复核、多模型 Rollout、Judge 重复性、正负区分度和泄漏分组报告。

## 正式 Benchmark 的晋升门槛

```text
真实轨迹或许可清楚的公开 Seed
-> 隐私、许可与输入恢复
-> 任务家族和泄漏组标注
-> 指令澄清但保留真实意图
-> 人工制作或复核 Golden
-> 原子 Rubric 与分层 Judge
-> Golden / 中等 / 负例 / 损坏文件校准
-> 三个强模型多次 Rollout
-> Judge 重复性与偏序报告
-> feedback / selection / final 分组切分
-> 冻结 Benchmark Release
```

只有完成最后一步的题，才参与论文主结果。公开合成样例和未审查的 273 条候选池都不能提前计入正式规模。
