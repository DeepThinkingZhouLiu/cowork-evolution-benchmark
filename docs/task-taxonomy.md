# 任务分类法 v0.2

## 为什么不能只分 PPT、Word、Excel、All

`PPT / Word / Excel / All` 只说明最后交什么文件，无法解释任务真正考了什么。同样是 PPT，一题可能是“根据数据做决策汇报”，另一题可能只是“把已有页面改成品牌模板”；它们对 Harness 的要求完全不同。如果论文只按文件类型报分，就看不出 Evolution 算法到底学会了抽取事实、计算、视觉排版，还是只记住了某个工具调用方式。

CoworkEvoBench 因此采用多轴标签：

```text
主领域
-> 任务家族
-> 操作类型
-> 输入模态与依赖范围
-> 核心能力
-> 约束画像
-> 难度层级
```

每道题只有一个主领域和一个主任务家族，但可以有多个操作类型、能力和约束标签。主领域用于论文主表分层；能力和约束用于分析 Harness 进化发生在哪里。

## 第一轴：主领域

| 代码           | 判定标准                                                   |
|----------------|------------------------------------------------------------|
| `ppt`          | 核心交付物是 PPTX，重点评估演示叙事、页面和视觉表达。      |
| `docx`         | 核心交付物是 DOCX，重点评估长文结构、编辑和格式保持。      |
| `xlsx`         | 核心交付物是 XLSX，重点评估数据、公式、图表和可复算性。    |
| `cross_office` | 至少两个 Office 交付物必须共同完成目标，并保持事实一致。   |

## 第二轴：任务家族

PPT 分为 12 个家族：

- `material_to_deck`：从报告、访谈、PDF 等材料生成演示文稿。
- `outline_to_deck`：把大纲扩成完整、可讲述的演示文稿。
- `data_to_deck`：从表格和指标中提炼结论并可视化。
- `template_based_generation`：在指定母版或品牌模板中生成内容。
- `content_editing`：增删改页面内容，同时保护未要求修改的内容。
- `visual_editing`：只改变布局、图片、图表或格式，不改变事实。
- `deck_polishing`：对已有草稿统一风格、层级和可读性。
- `deck_consolidation`：合并多份演示文稿、去重并形成统一叙事。
- `audience_adaptation`：针对高管、客户、技术或公众改写同一内容。
- `localization`：翻译并处理长度变化、术语和本地表达。
- `presentation_package`：同时交付 PPTX、讲稿、PDF 或附件。
- `deck_audit`：检查并修复事实、数字、版式或品牌问题。

Word 分为 8 个家族：

- `material_to_report`：从多份材料形成结构化报告。
- `outline_to_document`：把提纲扩成完整政策、手册或方案。
- `template_filling`：将事实准确填入合同、表单或公司模板。
- `editing_rewriting`：按语气、受众或风格要求改写已有文档。
- `redlining_review`：审阅合同或政策并保留可追踪修改痕迹。
- `formatting_fidelity`：统一格式、分页和品牌，同时保持原文内容。
- `merge_compare`：比较并合并多个版本，清楚呈现差异。
- `document_extraction`：从 PDF、扫描件或附件抽取事实并形成文档。

Excel 分为 14 个家族：

- `document_to_table`：从文档、图片或 PDF 提取结构化表格。
- `data_cleaning`：处理缺失、重复、格式、异常和类型问题。
- `table_transformation`：宽长表转换、字段映射、拆分和汇总。
- `formula_authoring`：新增正确、可复制、可重算的公式。
- `model_building`：构建预算、预测、估值或经营模型。
- `scenario_analysis`：设计基准、乐观、保守等情景和敏感性分析。
- `pivot_analysis`：以透视思路做多维聚合和钻取。
- `charting`：用恰当图表表达一个明确结论。
- `dashboard`：在同一工作簿形成可读、可交互的管理看板。
- `template_completion`：在既有模板中补齐数据和公式。
- `spreadsheet_repair`：修复损坏公式、引用、格式和工作表结构。
- `spreadsheet_audit`：识别错误、风险、异常和控制缺口。
- `multi_workbook_integration`：跨多个工作簿对齐字段并合并结果。
- `analysis_to_report`：完成分析并在工作簿或附加文档中解释结论。

跨 Office 分为 8 个家族：

- `extract_analyze_present`：从材料抽取数据，在 Excel 分析，再用 PPT 汇报。
- `research_to_deliverables`：把研究证据转成报告和演示等成套成果。
- `shared_source_multi_output`：从同一事实源生成多种交付物。
- `update_propagation`：把一个变更同步到 Word、Excel、PPT 等多个文件。
- `cross_file_consistency`：发现并解决多个文件之间的事实冲突。
- `template_driven_package`：按一组模板形成完整项目包。
- `review_and_revision`：根据评审意见修订多个相互关联的文件。
- `workspace_orchestration`：探索工作区、安排多步骤并完成成套交付。

## 第三轴：Benchmark 通用能力标签

Benchmark 通用能力标签固定为 `K1` 至 `K13`。其中 `K1-K5` 更偏内容与分析，`K6-K9` 更偏专业制作，`K10-K13` 更偏复杂工作流。每题至少标两个能力，避免把“会打开文件”误当成完整能力。

| 能力  | 含义                                                     |
|-------|----------------------------------------------------------|
| `K1`  | 从文字、表格、图像和文档中抽取关键事实。                 |
| `K2`  | 让数字、结论和来源保持可追溯。                           |
| `K3`  | 清洗、映射、合并和重组数据。                             |
| `K4`  | 构造正确、可复算的计算、公式和模型。                     |
| `K5`  | 比较、诊断、解释并形成业务判断。                         |
| `K6`  | 组织清楚、完整的专业叙事。                               |
| `K7`  | 局部编辑并保护未修改内容与格式。                         |
| `K8`  | 用布局、图表和视觉层级表达重点。                         |
| `K9`  | 遵循模板、品牌和交付规范。                               |
| `K10` | 联合多个文件并理解依赖关系。                             |
| `K11` | 把同一事实更新一致地传播到多个文件。                     |
| `K12` | 识别错误、风险、缺失和不一致。                           |
| `K13` | 规划并完成多步骤、多应用工作流。                         |

甲方需求文档已经用 `C1-C13` 定义了一套偏工具与交付形态的“单点能力”。为了避免同一编号出现两种含义，本项目不改写它们，而是在 `supplier_capability_ids` 中原样保留：`C1` 素材搜集、`C2` 内容结构化、`C3` PPT 指令执行、`C4` 版式设计、`C5` 图表可视化、`C6` 讲稿、`C7` 文档抽取、`C8` 公式建模、`C9` 格式转换、`C10` 交付自检、`C11` 多模态理解、`C12` 跨格式交付、`C13` 交互 HTML。论文能力分析以 `K` 标签为主，和甲方规格对齐时使用 `C` 标签。

## 第四轴：难度

难度采用等级与英文标签一一对应的四级体系：

| 等级 | 英文标签 | 含义                                                       |
|------|----------|------------------------------------------------------------|
| `L1` | `easy`   | 在冻结的 Agent 与预算下具有较高成功率。                    |
| `L2` | `medium` | 需要稳定的多步执行，成功率和得分明显低于 L1。              |
| `L3` | `hard`   | 存在较深的信息、操作或约束耦合，强 Agent 仍频繁失败。      |
| `L4` | `expert` | 接近当前 Agent 能力边界，但必须保持人类可解且 Judge 可靠。 |

四个主领域都必须分别覆盖 L1-L4，但 PPT、Word、Excel 和跨 Office 使用各自的域内判级规则。不同领域不能只依据页数、文件数、应用数量或制题者主观耗时直接横向判级；同一级别表示在冻结评测协议下相近的实测难度，而不是表面结构完全相同。

正式赋值必须在 Golden、Judge 和 Harbor 回放通过后，使用冻结的 Baseline Agent、模型、工具权限、时间预算和重复次数完成 Rollout。具体分数与成功率阈值在实验协议冻结时确定。未完成校准的题必须同时写成 `difficulty_level = "unassigned"` 和 `difficulty_tier = "unassigned"`，不能保留制题者预估。当前 148 道候选题全部处于这一状态。

## 论文中的使用方式

主表先报告总体、PPT、Word、Excel、跨 Office 的 Final Success Rate 与 Evolution Gain。副表再按任务家族、能力标签、难度、依赖范围和约束画像拆分。这样可以回答两个问题：算法有没有提升，以及提升来自哪里。

任务划分时，语义模板、来源文件、同一客户材料和同族派生题必须进入同一 leakage group。分类标签只能用于分层抽样，不能用来绕过来源级去重。
