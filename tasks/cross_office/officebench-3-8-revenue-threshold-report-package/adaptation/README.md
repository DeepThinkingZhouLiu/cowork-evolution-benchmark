# OfficeBench 3-8 收入门槛分析任务逐题适配记录

## 为什么选择这道题

上游 subtask 0 要求根据一份 2004–2023 年收入表，删除收入低于 200 万美元的年份，同时交付 Excel 和 Word。这是一个典型的“共享来源 -> 可复算分析 -> 管理报告”跨 Office 链路：Word 中的所有数字和结论都必须由 Excel 证据支撑，两份文件不能独立拼凑。

结构设计目标为 L2 / Medium：单一表格输入，但需完成二十年全量审计、严格门槛边界、原生公式、原生图表、双文件事实一致和证据边界。按项目规则，正式难度仍保持 `unassigned`，等待冻结多 Harness Rollout 后统一校准。

## 实际读入上下文的上游材料

- `tasks/3-8/subtasks/0.json`：本题选中的完整 Query 和原 Evaluator。
- `tasks/3-8/subtasks/1.json`至 `7.json`：全部七个同组变体，用于判断资产共享关系和避免拼题。
- `tasks/3-8/testbed/data/company_revenues.xlsx`：完整读取并渲染核对的二十年收入表；本题 Agent 输入为其逐字节副本。
- `tasks/3-8/testbed/data/score.xlsx`：已读取，它只与 subtasks 5–7 的学生分数分析有关，与 subtask 0 的收入门槛无关，因此不作为本题输入。
- `utils/evaluate.py`：上游通用评测入口。
- OfficeBench 根目录 `README.md` 和 `LICENSE`，固定 commit `b978b808667c32b52ce19a67ce1def1de9ae02b7`。

为保留审计链，本目录保存了选中 subtask、原 Evaluator 和 Apache-2.0 许可证的精确快照。

## 跨文件因果链

```text
company_revenues.xlsx
-> 20 年冻结来源表
-> 门槛状态、差额与排名公式
-> 17 个保留年份 + 3 个移除年份
-> 12 项公式汇总 + 原生趋势图
-> Word 规则、管理摘要、移除台账与证据边界
```

Judge 不信任 Golden 内的结果，而是从冻结输入重算全部真值，再分别检查 Excel 公式缓存、Word 事实和两文件一致性。

## 对上游的必要改造

- 保留上游全部年份、收入和 200 万美元门槛，不新增业务事实。
- 上游要求交付 `new.xlsx` 和 `report.docx`，本适配改为语义明确的固定文件名，并把“删除低收入年份”升级为保留来源、完整审计、筛选结果和管理报告的可追溯交付。
- 上游 Evaluator 只检查两个文件是否存在、Excel `B4=2793265` 和 Word 中是否有 `revenues`，无法防止错筛选、错数字、静态化公式或跨文件冲突。
- 本题人工重写 16 条 Rubric 与任务专属 Judge，覆盖完整真值、公式、原生表格/图表、跨文件事实、渲染可用性和无来源因果/预测。

## 许可、隐私与泄漏

来源为 Apache-2.0 的 OfficeBench 公开任务。上游表只含年份与收入，不含个人信息；按上游 benchmark 属性保守标记 `synthetic=true`。任何复用同一 `company_revenues.xlsx` 或相同真值的变体都必须归入 `officebench-3-8-company-revenues` leakage group，不得跨 split。
