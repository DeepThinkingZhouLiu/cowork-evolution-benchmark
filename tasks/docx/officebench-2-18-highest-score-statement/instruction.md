# Midterm recognition release-readiness review

The academic office received two frozen Excel sources:

- `nomination_shortlist.xlsx` is the four-row recognition shortlist.
- `detailed_midterm_register.xlsx` is the detailed Midterm 1 / Midterm 2 assessment register.

Create one editable Word working paper at exactly `/app/output/highest_score_recognition_review.docx`. Deliver no other file.

This is a release-control review, not an instruction to send a congratulatory letter immediately. Reconcile the shortlist against the detailed register before deciding whether any statement can be released. Treat each spreadsheet row as a separate assessment record. Because the files contain displayed names but no student IDs, do not merge repeated names or assume that same-name rows identify the same person.

The document must contain:

- a prominent release status and concise executive finding that identifies every detailed-register record tied for the highest Midterm 1 score, explains any shortlist omission or conflict, and does not call anyone the sole winner unless the evidence supports that claim;
- an audit snapshot with detailed-record count, distinct displayed-name count, Midterm 1 maximum, minimum and spread, and Midterm 2 maximum and minimum;
- a four-row shortlist reconciliation table preserving source order, with shortlist source row, name, listed Midterm 1, exact Name + Midterm 1 match result, matching detailed source row(s), and a control result;
- one separate, clearly labelled `DRAFT — NOT FOR RELEASE` recognition statement for each co-highest detailed record. Each statement must address the displayed name, state the Midterm 1 result and tie status, and avoid unsupported claims. Add a native Word comment to each draft label that cites its detailed-register row and, when applicable, its shortlist row or omission;
- a 20-row detailed evidence ledger preserving detailed-register source order. Include source row, displayed name, both scores, signed `Midterm 2 − Midterm 1` delta, direction, exact shortlist-pair status, and an evidence/control note. Do not collapse duplicate-name rows;
- a duplicate-name control table and release controls that state what must be resolved before publication and what cannot be inferred from the evidence.

Use Word-native headings, paragraphs, tables, comments and internal navigation. Include a Word table-of-contents field, bookmarks and working internal links from the navigation/drafts to the evidence ledger. Put the detailed ledger in a landscape section; repeat table headers and prevent row splitting. Use restrained professional styling, a control-status header, and PAGE / NUMPAGES fields in the footer. Set meaningful core properties.

Keep all output editable. Do not flatten content to screenshots, add macros/OLE objects, use external links, invent student IDs, courses, grades, GPA, instructor names, dates, award rules or eligibility conclusions, or include hidden answer keys.
