# 逐题改造记录：OmegaUse-OfficeVal officeval_018

## 为什么选择这道题

- 原始 Query 和两个 DOCX 输入来自公开数据集，不是本项目编写的场景、原始报告或格式要求。
- 输入是 84 页长报告，含 25 张表、31 组可见图形和 18 个原生图表，能真实考查长文结构理解、格式保持、题注语义和跨页排版。
- 上游提供了 Query、Rubric 和逐题 Verifier，可追溯；记录的人类完成时间为 251 分钟，符合长期 benchmark 中的高难度真实办公任务定位。

## 实际检查过的输入

- `公共书房运营规划书.docx`：386 个顶层段落、25 张表格、33 个 drawing 对象、18 个原生图表、2 个节；LibreOffice 原始渲染为 84 页。
- `报告排版格式要求.docx`：1 页，明确题目、摘要、五级标题、正文、图注、表注、表内文字、页边距和五套编号格式。
- 原报告实际题目为“青禾公共书房网络化运营与更新规划书”，并非上游 Rubric 写的“临海公共书房……”。
- 一个所谓图形实际上是全透明 PNG，没有可见内容；它被视为冗余占位对象，不虚构图题。
- 三处图形使用浮动锚点，其中末尾段落含两张不同图片；若不转为独立内联图形，无法实现稳定的一图一注。

## 上游 Rubric 和 Verifier 的问题

- Query 中的“公告书房”与输入文件名和报告内容不一致，本题仅校正这一明显错字。
- 上游 Rubric 和 Verifier 硬编码了输入中根本不存在的“临海公共书房……”题目，导致正确保留原题目也会被扣分。
- 上游 Verifier 的三级和四级标题候选正则互相重叠，同一段落会同时被要求使用两种互斥编号，无法同时满足。
- 上游二级标题分类器把“摘要”当成二级标题，又用不同字号判定它不合格。
- 上游对“表格不能断页”的实现要求长表完全放在一页，对 29 行、12 磅的真实表格不可行。本题按专业 Word 规则修正为“长表可连续跨页，不拆单行，续页重复表头”。
- 上游 Verifier 仍原样保存在 `tests/upstream_verifier.py`，不会把修正后 Judge 冒充成上游结果。

## CoworkEvoBench 的逐题改造决策

- 我们没有从空白文档生成这道题，而是从两个原始 DOCX 出发，逐段分析原文层次和图表语义。
- 七个章标题、29 个二级标题、30 个三级标题、28 个四级标题和 13 个五级标题由逐段语义检查后确定，不是用一条通用正则盲分。
- 31 条图注和 25 条表注的标题根据每个真实对象的上下文和数据内容逐一命名，Judge 检查连续编号、相邻位置和关键词，而不要求 Agent 复制 Golden 的整句文字。
- 为保持输入事实，Judge 比较原始长正文块、每张表的单元格文本、图形数和原生图表数；不只检查文件是否存在。
- 参考解法是 `officeval_018` 独有的显式段落映射和修复，不依赖、不调用任何批量造题器。

## 已完成的逐题验证

- 参考解法已从两个原始输入独立 replay，产生 86 页 DOCX，Golden SHA256 为 `cd9cee0c0cfb1a26b4b1fc91de9ab462ff887a5e33ef6a444e7e684f8b87a0ac`。
- Golden 已由 LibreOffice 实际渲染，并分页抽查标题层次、长表重复表头、浮动图形和末页两张图的题注位置。
- 上游 Verifier 在 Golden 上得分 `26/55`：其中图注、表注、表格格式、编号和大部分标题字体通过；其余主要失分来自上述硬编码错误和不可同时满足的规则，因此只作诊断证据，不作本题总分。
- 修正后的本项目 Judge 对 Golden 和从原输入重新 replay 的产物均给出 `1.0`；重放产物的 129 个 OOXML 包内容与 Golden 逐项相同，文件 SHA256 的差异只来自 ZIP 条目时间戳。
- 保留全部事实和题注，但漏做标题字体、正文段落格式和长表规则的中等缺陷样本得分 `0.730769`，低于 `0.75` 通过线；空目录、损坏 DOCX 和未作答原文均不能通过。
- Golden、中等缺陷、空目录和损坏文件的 Judge 结果均通过 `schemas/judge-result.schema.json`。
