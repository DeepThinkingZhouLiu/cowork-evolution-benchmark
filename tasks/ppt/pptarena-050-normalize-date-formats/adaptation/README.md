# PPTArena Case 50 逐题适配记录

## 适配契约

- 角色：演示文稿内容编辑。
- 输入：15 页制裁合规演示文稿，其中混合数字日期、日-月-年、序数词和缺失年份的表达。
- 真实意图：将所有可识别日期统一为 `Month Day, Year`，并根据同页上下文补齐缺失年份。
- 主交付物：`NormalizeDate_GroundTruth.pptx`。
- 不可妥协约束：37 个日期实例正确；月份大小写保持；非日期文字、顺序、页码、结尾页、空占位符、备注、媒体、几何和逐字符样式均保持。
- 候选设计目标：L2 / Medium；正式难度字段保持 `unassigned`，等待真实 Agent Rollout 后定标。

## 日期真值与 Golden 构建

- 本地逐页核对得到 37 个目标日期，分布在 14 个文本对象中。
- 覆盖 `25 February 2022`、`02/26/2022`、`18 of March 2022`、`March 12th 2022`、`first of September 2022` 和 `28 day of September – 10/12/1999` 等不同表达。
- 第 7、8 页的 `February 24` 与 `March 2` 从同页语境推断为 2022 年；1999 年范围的两端均按美式数字日期解析。
- 来源文本中的小写 `march` 与已规范的大写 `MARCH 11, 2022` 均保持原大小写。
- `build_golden.py` 只接受锁定 SHA256 的本题输入，并按文本 run 精确修改目标字符，不整框重写文本。
- 本地 Golden 保留输入的对象结构、段落数、run 字体、备注和媒体；只改变目标日期字符。

## 上游 Ground Truth 审计

- 上游 Ground Truth 的 37 个日期文本与本地人工核对结果一致。
- 上游文件同时删除了第 2、3、6 页的空占位符，这与“只改日期，其他对象不变”相冲突。
- 因此本地 Golden 不直接复制上游文件，而是从冻结输入执行最小的逐 run 日期编辑。

## Judge 设计

本地 Judge 不读取 Golden，不比较 Golden 哈希；它只使用冻结输入、上游任务契约和本题逐页核实的可重算真值。

- 从冻结输入独立重算 14 个目标文本对象和 37 个日期的期望内容。
- 对缺年份、数字日期语义、日期范围与月份大小写设置独立门槛。
- 按对象 ID 比较全部页面对象、几何、占位符类型、非日期文字、段落属性和逐字符字体。
- 比较备注与媒体哈希，检查结尾页、页码、空占位符、包关系、宏和可疑答案标记。
- 使用独立 LibreOffice profile 渲染输入与候选文件；屏蔽日期文本框后对比非目标像素，并检查 14 个日期区域可见。
- 允许 run 分段不同但文字顺序、逐字符样式和全部对象一致的合法答案，避免把 Golden 的内部 run 数量当作唯一答案。
