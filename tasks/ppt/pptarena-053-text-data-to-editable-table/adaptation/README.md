# PPTArena Case 53 逐题适配记录

## 适配契约

- 角色：房地产财务演示文稿编辑。
- 输入：1 页低收入住房税收抵免（LIHTC）演示文稿，右侧含一个财务数据文本框和一张空的 4×2 表格。
- 真实意图：将四组标签/数值从连续文本拆分到对应单元格，删除数据文本框，保持原生可编辑表格和原稿风格。
- 主交付物：`FillTablefromData_GroundTruthA.pptx`。
- 不可妥协约束：8 个单元格真值正确；原文本框已删除；只有一张 4×2 目标表格；原边框、填充、行高、列宽和主题样式保持；其他对象不变。
- 候选设计目标：L2 / Medium；正式难度字段保持 `unassigned`，等待真实 Agent Rollout 后定标。

## 真值与 Golden 构建

- 源文本框对应四行数据：`Revenue / 30% AMI Rents`、`Annual Actualized Income / $387,030`、`Annual Operating Expenses / ($420,300)`、`Annual Net Revenue / ($33,270)`。
- 冻结输入中的唯一 4×2 表格已预置不同行的填充、边框、字号与末行强调色，因此本地 Golden 直接填充该表格，不新建替代表格。
- `build_golden.py` 锁定输入 SHA256，删除对象 9 的数据文本框，填写对象 16 的表格，并将表格上移到右侧更合理的空间。
- 填写前后逐单元格比对 `tcPr`、表格 `tblPr`、行高和列宽；保存后再回读比对全部非目标对象与媒体哈希。

## 上游 Ground Truth 审计

- 上游 Ground Truth 的 8 个单元格文本、右列对齐、字体层级和表格位置可用。
- 但它在删除源文本框后，额外新增了一张与目标表格位置和尺寸完全相同的 4×2 表格，内容是本题未要求的 `50% AMI Rents`。
- 该表格被目标表格完全遮住，渲染时肉眼不可见，但会污染原生对象结构，也违反“其他元素不变”。
- 因此本地 Golden 不直接复制上游文件，而是从冻结输入执行最小、可解释的删文本框+填原表格操作。

## Judge 设计

本地 Judge 不读取 Golden，不比较 Golden 哈希；它只使用冻结输入、上游契约与逐页核实真值。

- 在候选文件中定位唯一原生 4×2 表格，逐单元格比对标签、金额、括号负数与列对应。
- 检查源文本框及其数据片段不再出现于表格之外，并要求页面仍只有 3 张原生表格和 8 个对象。
- 独立比对目标表格的 `tblPr`、8 个 `tcPr`、行高和列宽；检查左列标签、右列数值、字号、粗体和末行强调色。
- 逐对象保留标题、左侧正文、两张上方表格、图片、页脚和备注，并比较媒体哈希。
- 几何检查允许表格在右侧合理范围内小幅移动，但要求在页内且不与上方表格、左侧正文或页脚重叠。
- 使用独立 LibreOffice profile 渲染输入与候选；屏蔽源文本/目标表格编辑区后比较其他像素，同时检查表格区域有足够可见文字。
