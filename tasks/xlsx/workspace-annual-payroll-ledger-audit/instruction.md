# 年度工资账的逐月勾稽与单次扣税情景

输入 /app/data/input_files/完整年度工资管理系统_2019.xlsx。请交付 /app/output/annual_payroll_audit.xlsx，帮助财务复核12个月和年度汇总。源文件有16个页签，不能只复制年度总计；不要把页签名“应发”当成已证明的会计口径。

本题只审查提供材料的算术和口径，不判断税法、不重新算税率，也不确认实际银行付款。建立一个明确的“所有列示扣款（含个税）只扣一次”复核情景，个税金额取原数不变；该情景不代表已批准的补发工资。

## 交付接口

七个页签，第一行为表头。金额元，按下列列序；原数据与计算列严格分开。

1. 月度底稿：12个月×8人=96行，月份1到12、各月按原序。A月份；B:Y依次保留原表A:X的24列（包括序号、姓名、部门、职位、出勤、加班、金额、状态、备注）；Z来源。合计行、封面、查询链接不得混成员工记录；身份证、电话、地址不必复制进报告。
2. 年度底稿：8人按基础信息序号，A序号、B姓名、C部门、D职位、E:P原年度表12个月数、Q原年度合计、R原月均、S来源。
3. 月度勾稽：与底稿96行一一对应，A月份、B序号、C姓名；D重算应发（原G:M相加），E重算扣款（原O:S相加），F单次扣款后净额（D-E），G原税后实发（原V），H情景净额减原实发，I原应发减D，J原扣款减E，K原税前减(D-E)，L原实发减(原税前-原个税)。D:L均公式；不能用“异常”标签替代数值核对。确认原税前、实发与扣款列的关系，但不要篡改原数据。
4. 员工年度：8人，A序号、B姓名、C部门、D原月表实发年度合计、E原年度表Q、F两者差额(D-E)、G重算应发年度合计、H单次扣款情景年度合计、I情景减原实发、J原月表平均实发、K原月表最低实发、L原月表最高实发、M极差(L-K)、N原月表实发总体标准差、O变异系数(N/J)。D:O均可重算公式；按员工键汇总，不能靠所有表永远同一行假设。
5. 部门年度：技术部、财务部、销售部、人事部、行政部五行；A部门、B人数、C原实发年度总额、D人均原实发年度额、E员工年度额中位数、F情景年度总额、G情景增额、H重算应发年度总额。B:H原生公式；“人均年度”不是月度平均；中位数样本是员工年度额，不是96个月人混在一起。
6. 审查指标：A名称/B值，B2:B10依序公式计算：员工数、月度记录数、原实发年度总额、重算应发年度总额、个税列年度合计、单次扣款情景年度总额、情景与原实发差额、原年度汇总对月表不一致员工数、存在正情景差额的月度记录数。原列全部保留，不能把源年度表直接改为情景值。
7. 审计结论：至少三行，A主题、B源证据、C数值影响、D待核实动作。必须说明年度表是否与月表勾稽、应发/实发命名口径、扣款链里个税重复扣除的算术迹象与情景边界。不能断言真实税款错误、员工违法或工资已补发；发放状态只是源表文字，不是付款凭证。

至少一张原生图表比较各部门原实发与情景额；各表清楚金额单位、冻结首行、筛选。不要宏、外链、联网或大模型评分。Judge独立核对原值、重算、统计口径，再改变一笔绩效工资、个税和实发原数、打乱一个月份员工顺序，检验依赖链。允许等价公式和不同图表样式，按分项给部分分。
